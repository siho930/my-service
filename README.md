# uma_helper2

개인 PC에서 실행하는 우마무스메 육성 도우미입니다. 로그인·클라우드 업로드 없이 SQLite에 저장합니다. 기존 `uma_helper.html`과 독립된 앱입니다.

## 앞으로의 추천 원칙

모든 대회의 기본 추천 기준은 **한국 공략 우선 + 일본 동일 코스 실전 사례 보완**입니다. 한국 서버의 출시·밸런스·규칙을 검토한 뒤 의상을 특정한 3인 조합을 2~3개 제시합니다. LoH의 목표는 플래티넘4 달성이며 상위권 점수 재현을 요구하지 않습니다. 각 출처의 작성·확인 시점, 추천의 장단점과 실제 성적의 성격을 구분해서 표시합니다. 한국 공략이 아직 확인되지 않은 기존 일본 사례는 일본 자료라는 표시를 유지하며 한국 추천으로 둔갑시키지 않습니다. 자료 갱신 시에는 이 기준을 적용합니다. 공략을 주기적으로 자동 수집하는 기능은 현재 없습니다.

## 실행

`start.cmd`를 두 번 클릭하면 서버를 숨김 실행하고 브라우저를 엽니다. 주소는 http://127.0.0.1:8766 입니다. Node.js 24 이상이 필요하며, 이 PC의 Codex 내장 Node도 자동 탐색합니다. 종료는 `stop.cmd`로 합니다. 이미 실행 중이면 start.cmd는 기존 앱을 엽니다.

터미널에서는 `node --disable-warning=ExperimentalWarning server.mjs`로 실행하고 Ctrl+C로 종료할 수 있습니다.

### 인터넷 주소 연결

앱의 첫 화면은 `public/index.html`입니다. Node.js 서버가 `/`에서 이 파일을 제공하고, 같은 주소의 `/api/` 요청을 처리해 SQLite에 저장합니다. 앱을 인터넷 주소에서 사용하려면 Node.js 서버를 실행한 상태에서 도메인으로 들어오는 요청을 서버에 전달해야 합니다.

현재 PC에서 계속 실행할 경우, HTTPS 리버스 프록시나 터널의 대상 주소를 `http://127.0.0.1:8766`으로 설정하세요. 도메인의 루트 경로 `/`와 `/api/`를 포함한 모든 요청을 같은 서버로 전달합니다. 앱에 로그인 기능이 없으므로 개인용으로 연결할 때는 프록시나 터널에서 접속자를 제한하세요. 연결 후 도메인의 `/`에서 첫 화면이 열리고 `/api/health`가 `ok: true`를 반환하는지 확인하세요.

## 사용

1. 한국 서버에서 다음에 시작할 챔피언스 미팅과 리그 오브 히어로스를 각각 1개씩 표시합니다. 선택 시 코스·인원·계절·날씨·마장을 적용합니다. LoH의 날씨·마장은 랜덤이므로 계산용 가정값으로 변경할 수 있습니다.
2. 한국 공략과 일본 동일 코스 사례를 대조한 3인 조합을 대회별 2~3개 표시합니다. 각질 필터로 조합을 바꾸지 않습니다. 구성원을 누르면 그 말의 작전·계승·편성·스킬 상세가 적용됩니다. 성적은 작성자의 자기 보고이며 공식 전체 순위 DB나 승률 추정이 아닙니다. 의상과 출처, 주의점을 각 조합에 표시합니다. 보유 모드에서는 미보유 멤버를 그대로 표시하며 실제 보고 조합을 임의로 대체하지 않습니다.
3. 부모 2명과 각각의 조부모 2명을 확인합니다. 공략 후보와 기초 상성을 비교하며 같은 가지의 부모 중복을 제외합니다. 등록한 개체를 선택하면 실제 인자·G1·부모 연결을 적용합니다.
4. 인자작/고점작을 전환합니다. 한국·일본 공략의 역할과 필요 스킬로 6장을 편성합니다. 보유 모드에서는 등록 레벨을 적용하고 부족한 슬롯 중 최대 1장만 대여로 채웁니다. 나머지는 부족으로 표시합니다.
5. ‘선택 편성 스킬 계산’을 누르면 해당 육성마의 고유·초기·각성·진화, 편성 카드의 힌트·이벤트, 부모의 계승 스킬을 평가합니다. 각성/이벤트/진화 조건을 달성해야 실제 취득할 수 있습니다. 조부모의 흰 인자는 별도 보유 정보가 없어 포함하지 않습니다.
6. 일본 조합 추천과 상세 스킬 시뮬레이션은 독립적입니다. 상세 계산 작전을 바꿔도 조합이나 보고된 성적은 바뀌지 않습니다.
7. 보유 목록은 자동 저장됩니다. ‘현재 육성 계획 저장’은 당시 결과를 스냅샷으로 저장합니다. 백업/가져오기는 보유 목록·설정·계획을 지원하며, 가져오기는 병합합니다. 계산 캐시는 백업에 포함하지 않습니다.

- `vendor/umamusumedb` (MIT): 캐릭터 273종, 서포트 568종, 기본 스킬 1,953개 및 이미지·한국어 텍스트.
- `vendor/uma-tools` (GPL-3.0): 원본 도구와 일본판 비교 규칙 참고 자료를 보존합니다.
- `vendor/uma-course-skill-ranker` (GPL-3.0): 코스 119개와 분석·엔진 소스. 기본 글로벌 필터를 일본 데이터로 교체합니다.
- `vendor/uma-skill-tools-jp` (GPL-3.0-or-later): 일본판 원본 효과·조건·진화 데이터 대조. GameTora 현재 manifest의 일본 기본값·계승 효과·진화 연결을 정규화합니다.
- 이미지·게임 텍스트·제3자 데이터의 권리는 각 권리자에게 있습니다. 코드 라이선스만으로 모든 자료의 재배포 권리가 보장되는 것은 아닙니다.
- 한국 서버 출시일과 최신 밸런스는 검증하지 않았습니다. JP/글로벌 자료와 한국어 번역이 혼합되어 있습니다. 개인 보유 목록으로 실제 이용 범위를 제한하세요. 한국 서버 출시일은 DB에서 NULL로 보존합니다.
- 기초 상성은 기존 작업 폴더의 `uma-affinity-relations.js`를 `data/affinity.json`으로 보관한 별도 자료입니다. 자동 갱신하지 않습니다.
- 카드 기본 효과는 해당 레벨 이하의 가장 가까운 공개 값으로 계산합니다. 임의 레벨의 중간값을 보간하지 않으며 고유 보너스는 미반영입니다. 인자작은 레이스 보너스·힌트 빈도 가중치를 높입니다. 정확한 식은 `lib/recommend.mjs`에 있습니다.
- 계산 엔진은 일본 기본값으로 정규화한 스킬을 지원합니다. 지원 개수는 앱에 표시하며, 미지원 효과·조건은 이유를 붙여 0점과 구분합니다. 조건 충족률은 지능 체크를 생략한 가정하의 값으로 실전 발동률이 아닙니다.
- 스킬마다 동일 시드로 유무를 비교합니다. 고정 능력치 1600/1300/1100/800/1100, 최상, 거리 S·마장/각질 A. 각 순위에 대해 예비 12회, 유효 효과 64회. 순위 중심 도주 .12·선행 .38·선입 .62·추입 .8, 표준편차 필드 크기의 .22인 가우스 가중치입니다. 외부 조건 일부는 충족 가정이며 시너지·실제 상대 구성을 반영하지 않습니다.
- SP는 해당 단계 비용입니다. 하위 스킬의 취득 비용은 별도로 더해야 하며 공통 힌트 레벨로 비교합니다. 고유 등 비용 없는 스킬에는 SP 효율을 표시하지 않습니다.

## 파일

- `data/uma_helper2.sqlite`: 통합 DB, 출처 커밋, 보유 목록, 설정, 계획, 계산 캐시
- `public/`: 화면, 스타일, 브라우저 앱과 시뮬레이션 Worker
- `src/simulation.worker.ts`: 다운로드한 ranker 엔진을 사용하는 Worker 어댑터
- `vendor/`: 세 저장소의 원본 소스·라이선스 및 esbuild 0.25.12 (MIT)
- `scripts/import.mjs`: DB를 트랜잭션으로 갱신합니다. 개인 데이터는 유지합니다.

스냅샷 출처 커밋과 가져온 시각은 앱의 ‘데이터 출처’ 화면에서 확인합니다. 새 데이터 반영은 앱 종료 → `update.cmd` → `start.cmd` 순서입니다. 새 저장소 구조가 바뀌면 갱신이 실패할 수 있습니다. 그 경우 로그를 확인하고 기존 DB를 사용하세요.

`node --disable-warning=ExperimentalWarning --test tests/*.test.mjs`로 DB·추천·시뮬레이터 검증을 실행합니다.

## 인자·G1 개체 기록과 계승 계산

사이드바 **인자 · G1 기록**에서 육성 결과별로 개체를 저장합니다. 같은 의상도 여러 개체를 등록할 수 있습니다. 청색·적색·녹색 인자는 각각 최대 하나, 기타 인자는 이름과 1~3성을 기록합니다. G1/Jpn1 우승 목록, 전체 기록 확인 여부, 부모 두 개체와 메모를 SQLite `veterans` 테이블에 저장합니다. 조부모는 부모 개체에 연결된 실제 기록을 사용하며 임의 후보로 채우지 않습니다. 부모로 사용 중인 개체는 연결 해제 후 삭제할 수 있습니다.

계승 설계의 부모 개체 선택에서 적용합니다. 미선택 시 공략 후보를 보여줍니다. 개체 정보는 JSON 백업·복원에도 포함되며 기존 백업도 사용할 수 있습니다. 인자 이름은 직접 입력하며 스킬 이름이 DB와 정확하게 일치하고 하나로 식별될 때 효율표에 확률 획득 경로로 추가합니다. 녹색 인자가 미입력된 실제 개체의 고유 계승을 확보했다고 표시하지 않습니다.

기초 상성은 육성마/부모1, 육성마/부모2, 부모1/부모2의 2인 공통 그룹 3항과 육성마/부모/각 조부모의 3인 공통 그룹 4항을 합산합니다. 현대 규칙의 공통 G1 가산은 부모끼리 1쌍과 부모/조부모 4쌍의 공통 우승 레이스 종류 수 × 3입니다. 같은 레이스의 클래식·시니어 우승은 중복 가산하지 않습니다. 인자 별 수는 상성 점수에 가산하지 않습니다. 미입력·누락 상성 자료는 미확인으로 처리하고 확인된 부분합을 표시합니다. 모든 기초 항과 G1 기록이 확인될 때만 △/○/◎(51/151 경계)를 표시합니다. 상성 점수는 인자 획득률이나 힌트 레벨 보장이 아닙니다. 현재 수기 목록은 국내 G1/Jpn1만 포함하며 해외 레이스는 제외합니다.

## 한국·일본 공략 기반 서포트 편성

`data/support-guides.json`을 SQLite `support_guides`에 동기화합니다. 삿포로 LoH 도주·선행·추입, 교토 CM 선입·선행·추입 각각 인자작/고점작과 CM 디버프 지원역 2개로 총 14개 규칙입니다. 무인도 시나리오에서 카드 ID·역할·후보 순서·주요 스킬·선택지·출처·확인일을 저장합니다. 앱 시작과 DB 가져오기에서 동기화하며 개인 기록은 유지합니다. 재작성은 `node scripts/build-support-guides.mjs`, 조회는 `/api/support-guides`입니다.

한국 LoH 육성론(6228503/6228505/6228530), 인자작(6228501/6220712), 한국 CM 공략(6230039) 편성 이미지와 일본 우마무스메 라보의 동일 코스 육성론을 대조했습니다. 한국 자료 중 일본 공략의 한국어 정리 글도 포함됩니다. 인자작과 지원역은 필요 스킬·DB 획득 경로로 재구성했으며, 원문 추천 6장이나 성적 편성이라고 주장하지 않습니다. CM 이미지의 타입 표기 오기는 카드의 실제 타입으로 표시합니다. 반영 범위·작성일(확인된 경우)·확인일은 sources에 보존합니다.

공략 후보 안에서 6장 충족 → 주요 스킬 경로 → 공략 후보 순서와 등록 레벨 순으로 비교합니다. 슬롯 전체를 함께 탐색해 대여 최대 한 장을 배분하며 육성마와 같은 캐릭터·편성 내 중복을 제외합니다. 임의의 미래 카드를 채우지 않고 후보 부족과 누락 경로를 표시합니다. 기본 효과 점수는 후보 내 보조 비교에만 씁니다. LoH는 플4용 스태미나/금회복 포함 기본안이고 CM은 에이스와 지원역을 구분합니다. 자체 만리일공이 있으면 스칼렛의 톱 러너를 추천하는 등 확인한 분기를 적용하고 제외한 금스킬은 카드 이벤트 획득 경로에서 뺍니다. 효율표와 저장한 계획에도 반영됩니다.

## 일본 서버 기준 계산 엔진

GameTora 공개 manifest의 skills/evolutions 일본 기본값을 사용하며 글로벌 override를 적용하지 않습니다. 일본 원본 라이브러리는 [alpha123/uma-skill-tools](https://github.com/alpha123/uma-skill-tools), 비교 규칙은 [uma-tools 일본 umalator](https://github.com/alpha123/uma-tools/tree/master/umalator)를 대조했습니다. `data/jp-manifest.json`, 원본 JSON, 정규화 JSON과 DB의 `engineInfo`에 출처·해시·시점을 보존합니다. 스킬 DB 총 2,235개(현재 스냅샷) 안에서 검증한 효과와 조건만 계산 대상으로 연결합니다. 고유·계승 고유의 원본 효과를 각각 사용하고, 일본 진화 연결과 해금 조건도 원본 링크로 보존합니다. 일본 데이터 적용이 한국 출시나 동일 밸런스를 보증하지 않습니다.

JP 비교 어댑터는 양쪽 주자에 지구력 승부를 적용합니다. 글로벌 엔진의 수정본은 건드리지 않고 원본 compare.ts에서 GPL 파생 파일 `src/generated/jp-compare.ts`를 생성합니다. 새 엔진 버전은 새 캐시 키를 사용하며 구버전 엔진 결과의 저장 요청은 거절합니다. 보유 목록·개체·기존 저장 계획은 유지됩니다.

선행 스킬 발동, 일부 발동 횟수·상대 행동은 충족 가정의 조건부 비교이며 해당 행에 표시합니다. 스틸의 충동 발동 조건 등을 실제 육성 빌드에서 검증한 확률로 해석하면 안 됩니다. 미구현 효과 유형, 추가 발동, 대상 상세 지정, 미검증 가변 배율·조건은 숫자를 출력하지 않습니다. 파서·필터의 런타임 예외도 0마신으로 숨기지 않고 오류로 표시합니다. 순위 분포·고정 스탯·지능 체크 생략 등의 기존 근사는 유지되며, 전체 일본판 레이스를 정밀 재현하는 엔진은 아닙니다.

수동 갱신은 앱 종료 후 update.cmd입니다. 내부 순서는 저장소 갱신 → 공개 manifest 기반 일본 원본 다운로드 → `scripts/build-jp-data.mjs` → JP alias를 적용한 worker 번들 → SQLite 가져오기입니다. 워커 빌드는 `node scripts/build-worker.mjs`로 수행해 JP 비교·분석 alias를 함께 적용합니다. 테스트는 `node --disable-warning=ExperimentalWarning --test tests/*.test.mjs`입니다.


## 코스 유효율

효율표의 ‘조건 충족률’을 **코스 유효율**로 교체했습니다. 같은 코스·스탯·시드에서 스킬 유무를 비교한 개별 표본 중 **0.05마신(12.5cm) 이상 이득**이 난 표본의 비율을 순위 분포로 가중합니다. 미발동뿐 아니라 발동해도 이득이 없거나 기준보다 작은 표본도 무효입니다. 100%라는 표시는 스킬 발동률·실전 승률·지속시간의 유효 비율을 의미하지 않습니다. 기대 이득 열은 여전히 모든 표본의 평균 마신이며, 유효율과 함께 비교합니다. 코스 유효율순 정렬도 제공합니다.

순수 가속 스킬에는 **가속 유효**를 추가로 표시합니다. 같은 효과를 종반 최적 타이밍에 사용했을 때의 가속 단독 이득을 기준으로, 그 절반 이상을 얻은 표본 비율입니다. 복합 속도·가속 스킬은 속도 효과가 가속 효율로 오인되지 않도록 이 보조값을 표시하지 않습니다. 회복은 현재 고정 스탯에서 회복이 실제 거리 이득으로 이어지지 않으면 0%가 될 수 있으며, 디버프·스태미나 부족 빌드의 회복 가치를 부정하는 뜻은 아닙니다.

원본 분석의 표본 결과를 재사용하므로 유효율을 위해 시뮬레이션을 중복 실행하지 않습니다. 추가 메타데이터는 SQLite 결과의 `u`(유효율), `ut`(0.05마신 기준), `au`(순수 가속 유효율, 해당할 때)입니다. 이전 `r`은 발동 진단용으로 유지하지만 유효율로 재해석하지 않습니다. 새 워커 버전으로 캐시를 분리하며 구형 결과는 재계산합니다. `scripts/build-jp-data.mjs`가 GPL 파생 분석 어댑터를 생성하고 `scripts/build-worker.mjs`가 빌드합니다.


## 코스 전체 스킬 목록과 획득 경로

효율표는 현재 6장 편성에서 얻는 스킬에 제한하지 않고 선택 코스·각질에서 사용 가능한 전체 후보를 표시합니다. 거리·마장 종류·회전·코스 ID·계절·각질·경사와 발동 구간의 교집합이 맞지 않는 항목은 숨깁니다. 외부 조건·스탯·선행 스킬 조건은 실패로 간주하지 않으며, 문법이나 자료가 부족한 경우 미확인으로 남깁니다. 발동 표본이 없거나 유효율이 0%라는 이유만으로 회복 등 합법적 후보를 삭제하지 않습니다. LoH 랜덤 날씨·마장은 현재 계산용 기본값과 달라도 유지합니다.

다른 육성마의 본체 고유·전용 진화와 부정적 스킬, 현재 무인도(시나리오 11) 밖 진화는 제외합니다. 계승 고유와 계승 진화는 별도 후보이며 현재 육성마의 동일 본체 고유와 겹치는 계승판을 중복 표시하지 않습니다. 무인도 시나리오 진화는 추가 후보로 포함하고 현재 편성에서 원본 스킬을 얻을 수 있으면 조건부 진화 경로를 표시합니다.

각 행에 ‘현재 편성 경로’ 또는 ‘추가 준비’를 표시합니다. 육성마·서포트·부모·조부모 인자의 기존 경로 표시는 유지되며, 해당 경로가 없는 후보도 다른 카드·인자 등을 준비할 수 있도록 표시합니다. 힌트 발생·선택지·진화·계승이 확정되었다는 의미는 아닙니다. 획득 경로 필터로 전체/현재 편성 경로/추가 준비를 고를 수 있습니다. 계산 버튼도 코스 전체와 현재 편성만으로 구분하고 이미 계산한 유효 결과는 재사용합니다. 이 필터는 `src/course-filter.ts`를 Node ESM으로 빌드한 모듈을 서버에서 사용합니다.
